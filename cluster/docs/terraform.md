# Terraform + Terragrunt (planned)

Not built yet. This is the plan for moving Talos machine config and the cluster bootstrap from hand-run `talosctl` + `helmfile` into Terraform, orchestrated by Terragrunt. Today's flow: [bootstrap.md](bootstrap.md), [../talos/README.md](../talos/README.md).

## Why

- Talos config is regenerated by hand (`gen config` → `machineconfig patch` → `apply-config`) per node; drift between patches and nodes is invisible.
- `secrets.yaml` and `talosconfig` live out of band, gitignored.
- Adding the 2 control planes for HA means repeating every step per node.

## Layout

```
infra/
├── root.hcl                     # remote state, provider versions, common inputs
├── modules/
│   ├── talos/                   # schematic, secrets, machine configs, bootstrap, kubeconfig
│   └── bootstrap/               # onepassword-credentials Secret + helmfile hand-off
└── live/homecloud/
    ├── talos/terragrunt.hcl     # nodes map, versions
    └── bootstrap/terragrunt.hcl # dependency "talos" → kubeconfig
```

State backend: decide at build time (S3-compatible bucket, e.g. Cloudflare R2, keeps it off-cluster). It holds the Talos secrets, so it must be encrypted and private.

## `talos` module (`siderolabs/talos` provider)

| Resource                                                       | Replaces                                                                              |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `talos_image_factory_schematic`                                | Clicking through factory.talos.dev; `SCHEMATIC_ID` in `.mise.toml`.                   |
| `talos_machine_secrets`                                        | `talosctl gen secrets`. **Import** the existing `secrets.yaml`, never regenerate.     |
| `data.talos_machine_configuration` (per role)                  | `talosctl gen config`, with `config_patches` = the files in `cluster/talos/patches/`. |
| `talos_machine_configuration_apply` (per node)                 | `machineconfig patch` + `apply-config`. Per-node patches (hostname, IPs) inline.      |
| `talos_machine_bootstrap`                                      | `talosctl bootstrap` - once, first control plane.                                     |
| `talos_cluster_kubeconfig` / `data.talos_client_configuration` | `talosctl kubeconfig` / `talosconfig`. Output to gitignored files.                    |

Nodes are a map input (`{ cp1 = { ip = "10.10.17.5", role = "controlplane" }, w1 = {...} }`), so going 1 → 3 control planes is two map entries.

Talos/Kubernetes _upgrades_ stay on `mise run talos:upgrade` / `talos:upgrade-k8s` - the provider applies config, it doesn't orchestrate rolling OS upgrades.

## `bootstrap` module

- **1Password credential**: the `carlpett/sops` provider's `data "sops_file"` decrypts the existing [`../bootstrap/onepassword-credentials.sops.yaml`](../bootstrap/) with the local age key, and a `kubernetes_secret` creates `external-secrets/onepassword-credentials` from it. This replaces the helmfile presync hook. (Alternative if the age key should leave the picture: `1Password/onepassword` provider, `data "onepassword_item"` authenticated by `OP_SERVICE_ACCOUNT_TOKEN`.)
- **Talos secrets**: same pattern - SOPS-encrypt `secrets.yaml` into the repo and feed it to `talos_machine_secrets` via `sops_file`, so it's versioned instead of out of band.
- **Cilium + ArgoCD**: keep [`../bootstrap/helmfile.yaml`](../bootstrap/helmfile.yaml) as the source of truth; Terragrunt runs it after `talos` via an `after_hook` (`mise run bootstrap`). Moving the releases into `helm_release` would duplicate what ArgoCD then owns, so don't.

## Migration checklist

1. Create state backend; add `terraform`, `terragrunt` to `.mise.toml`.
2. `talos` module against the **existing** cluster: import `talos_machine_secrets` from `secrets.yaml`, then `plan` must show no config changes to the nodes beyond ordering noise. Fix patches until it does.
3. Apply; delete the manual `gen config`/`apply-config` sections from `cluster/talos/README.md`.
4. `bootstrap` module: import the existing `onepassword-credentials` Secret, drop the helmfile presync hook.
5. Update CLAUDE.md, [bootstrap.md](bootstrap.md), README roadmap.

## HA (1 → 3 control planes)

Add two control-plane entries to the nodes map and apply. Go straight from 1 to 3 - two-node etcd is worse than one. Then raise Longhorn replica counts (`gitops/infrastructure/longhorn/values.yaml`).
